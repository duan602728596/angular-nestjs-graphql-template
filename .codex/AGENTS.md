# Language Preferences

- 默认使用简体中文回复。
- 技术术语可以保留英文，并在必要时使用中文解释。
- 代码、变量名、函数名、命令、文件路径保持原样。
- 报错信息保留英文原文，并使用中文解释原因。
- 代码注释和文档默认使用简体中文。

# TypeScript 编码规范

- TypeScript 代码应尽可能使用明确的类型标注。
- 函数参数和返回值必须显式标注类型。
- 当变量、常量或类属性的类型无法从声明中直观确定时，必须显式标注类型。
- 对象结构优先使用 `interface`，联合类型、交叉类型、类型别名和工具类型优先使用 `type`。
- interface定义的类型以"I"开头，type定义的类型以"T"开头。
- 避免使用 `any`。对于确实无法确定类型的值，使用 `unknown`，并通过类型收窄进行处理。
- 不要使用不必要的类型断言（`as`）或非空断言（`!`）。
- 优先使用具体类型，避免使用过于宽泛的类型，例如 `object`、`Function` 或 `Record<string, any>`。
- 使用泛型保留类型之间的关联关系，不要为了简化代码而牺牲类型安全性。
- 所有公共 API、导出函数、方法和接口都必须具有明确的类型定义。
- 不要为了绕过 TypeScript 类型错误而弱化现有类型定义。
- 禁止引入隐式 `any`。
- 完成任务前，确保代码能够通过 TypeScript 类型检查。
- 只有当类型无法从依赖包中import时，才能省略。

## Angular 与 TypeScript 规范

- 使用 Angular Signals 进行响应式状态管理。
- 使用 `inject()` 进行依赖注入。
- 对不应重新赋值的属性优先使用 `readonly`。
- 避免不必要的订阅，并正确管理 RxJS 订阅的生命周期。
- Angular Service、Component 和 Tiptap Extension 必须使用严格的 TypeScript 类型定义。
- 严禁使用 `any` 绕过 Angular 模板类型检查或依赖注入相关的类型问题。
